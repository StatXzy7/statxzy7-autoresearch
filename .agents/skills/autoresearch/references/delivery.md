# 交付检查

按任务实际目标逐项核对，不为未执行的内容填成功。检查结果引用具体文件、运行 ID、哈希或日志位置；自行写出的结论不是它自己的证据。

| 检查内容 | 核对依据 |
|---|---|
| 任务和方法 | 目标、可写接口、输入输出和实际评价调用链一致 |
| 协议和数据 | 数据身份、划分、预处理、seed、质量要求和预算已固定 |
| 基线 | 对照来源清楚、实现健康、正式运行完整，实际训练量可比 |
| 实验记录 | 成功、失败、超时均保留；指标关联真实产物及代码/配置身份 |
| 比较 | 同协议全部正式重复，聚合规则未随结果改变 |
| 目标标定 | 需要时核对 B/R/U、证据强度、不裁剪公式和已声明阈值 |
| 私有评价 | 权限和评分边界实际验证，最终数据未参与选方法 |
| 运行配置 | 解释器、设备、模型及工具通道有真实验证，预算限制落实 |
| 最佳恢复 | 完整源码、配置和必要模型可恢复，干净进程重跑有结果 |
| 最终结论 | 原始指标、差值、波动、成本和限制与证据一致 |

无需额外功能的普通实验不强制构建挑战任务或多 Agent 对比；不适用项写明理由。用户要求的功能缺失时记录未完成，不能用不适用掩盖。

报告至少包含研究目标、实际范围、环境、对照与最佳方法、协议、结果表、失败记录、复现命令和未完成事项。使用 [摘要模板](../assets/run-summary.json) 汇总各结论；字段为空或状态为 `NOT_RUN` 时表示尚无对应证据。

交付前从干净目录检查依赖、路径和启动命令。导出只包含所需源码、配置、模型位置和公开说明；凭据、私有标签及不允许分发的数据不随包导出。对可分发产物生成文件清单与哈希，确保收到的版本对应已验证版本。
